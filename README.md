# Slack文字絵文字

Slackのカスタム絵文字登録画面で、文字絵文字を作成して登録欄へ反映するChrome拡張です。画像のダウンロード・ファイル選択・リネームを省けます。

## 導入

配布ZIPを使う場合、ZIPを保存して展開し、展開したフォルダを継続して使う場所に置いてください。ソースから導入する場合は、下記のビルドで生成した `dist/` を使います。

1. Chromeで `chrome://extensions` を開き、デベロッパーモードをオンにします。
2. 「パッケージ化されていない拡張機能を読み込む」で、`manifest.json`、`content.js`、`font-worker.js` が入ったフォルダを選びます。ZIPそのものは選択しません。
3. 一覧に「Slack文字絵文字」が表示され、有効になっていることを確認します。
4. Slackのカスタム絵文字登録ページ `https://<workspace>.slack.com/customize/emoji` を再読み込みします。

以前の検証用拡張「Slack Emoji Upload Spike」を使っている場合は、二重表示を避けるためオフにしてください。読み込み元のフォルダは、拡張を使う間は移動・削除しないでください。

## 使い方

1. Slack登録ページで絵文字追加ダイアログを開きます。
2. 文字・改行・フォント・文字揃え（中央／左／右）・文字色・背景色／透過を指定します。
3. プレビューを確認し、Slackで使う登録名を入力します。
4. 「登録欄に反映」を押します。
5. Slack側のプレビューと名前を確認し、Slackの「保存する」を押します。

文字や色を変更したら、再度「登録欄に反映」を押します。「反映済み」は登録欄に渡ったことを表します。絵文字の登録はSlackでの保存後です。

## 更新・無効化

ソースから利用する場合は `npm run build` で再ビルドします。ZIPから更新する場合は新しいZIPを展開し、読み込み元フォルダの3ファイルを置き換えます。その後、Chromeの拡張機能画面で「Slack文字絵文字」の再読み込みを押し、Slackページも再読み込みしてください。

利用を止める場合は拡張機能画面でオフにします。削除しても、すでにSlackへ登録した絵文字は残ります。

## 対応範囲と制限

- PC版Chromeの日本語Slack登録ページで確認済み（macOS、Chrome 156）。Slackへのログインと本人の絵文字追加権限が必要です。
- 対象は `/customize/emoji` の追加ダイアログです。Slackデスクトップアプリ内やメッセージ画面内の絵文字ピッカーは対象外です。
- 文字色と背景色はカラーピッカー、またはHEXコード（例：`#EC71A1`）で自由に指定できます。3桁の短縮表記や先頭の`#`なしも使えます。背景の透過はチェックボックスで切り替えます。
- 出力は128×128pxの静止PNG、128,000バイト未満です。
- 「縦に伸ばして埋める」は初期値オン。文字全体を上下8pxの余白内まで縦方向に拡大します。オフでは元の縦横比を維持します。
- 文字揃えは中央（初期値）・左・右から選べます。左右は8pxの余白内で揃え、選択は下書きに保持します。
- 文字は4行まで、1行12書記素までです。結合文字を途中で分割しません。
- 可読性はプレビューを見て判断してください。小ささによる警告・短縮案内・登録制限はありません。
- フォントはゴシック体・太いゴシック体・明朝体・丸文字・ポップの5種類です。初期値は太いゴシック体。全書体を太めに描画し、太いゴシック体はさらに強く太らせます。選択は下書きにも保持します。
- 利用時にGoogle Fontsから取得します。ゴシック体はNoto Sans JP 700、太いゴシック体はNoto Sans JP 900、明朝体はNoto Serif JP 900、丸文字はM PLUS Rounded 1c 900、ポップはMochiy Pop One 400です。太めの輪郭補正も適用します。
- 読み込み中は「フォントを読み込み中…」と表示し、画像生成・反映を止めます。通信失敗時はエラーを表示します。同じページ内で取得済みの文字範囲は再利用し、ブラウザの通常のHTTPキャッシュも利用します。永続的なオフライン動作は保証しません。
- 名前の重複・使用可能文字などの最終判定はSlack側が行います。
- ダイアログを閉じても下書きは同じページのメモリに残ります。ページの再読み込み・移動・終了で消えます。
- GIF、画像ファイル取り込み、一括登録、履歴・テンプレート保存には対応していません。
- Slackの画面構造が変わると、表示・反映できなくなる場合があります。

## アクセスとデータ

コンテンツスクリプトの適用先は `https://*.slack.com/customize/emoji` と末尾スラッシュ・クエリ付きの同ページに限定しています。このページのDOMを読み書きします。Cookie取得と拡張ストレージは使用しません。Google Fonts取得のため `fonts.googleapis.com` と `fonts.gstatic.com` へのhost_permissions、およびService Workerを使用します。更新後の権限確認が表示された場合は、この2ドメインのフォント取得用です。

Googleへは選択書体・太さのCSSリクエストと、入力に必要なUnicode範囲のフォントファイルのリクエストを送ります。入力文章を含む `text=` パラメーター、登録名、生成画像はGoogleへ送信しません。Googleには通常の通信情報や要求したフォント範囲が伝わります。リクエストはCookie・Refererなしで行います。

フォントのバイナリデータのみを読み込み、外部JavaScriptは実行しません。自動保存ボタン操作はありません。入力イベントに反応してSlack側が検証・アップロードなどの通信を行う可能性はあります。

## 開発・ビルド・配布

Node.js 24とPython 3で確認済みです。外部依存パッケージのインストールは不要です。

```sh
npm test
npm run build
npm run package
```

`dist/` がChrome読み込み用フォルダです。`npm run package` はビルド後、`releases/slack-emoji-0.6.6.zip` とSHA-256ファイルを生成し、ZIPの展開内容がdistと同一であることを検証します。ZIPにはmanifest・画面用スクリプト・フォント取得用スクリプトの3ファイルのみ含まれます。`dist/` はGitに含め、配布ZIPは生成物としてGitの対象外にしています。

Chrome Web Storeへの公開はしていません。別プロファイルでの導入確認は個人利用のため省略しています。
