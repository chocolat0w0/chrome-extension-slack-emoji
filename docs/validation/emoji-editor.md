# Step 3：エディター実装・検証

状態: 単独エディターを実装し、Chromeで確認済み。Slackへの組み込みはStep 4。

## 構成の変更

小規模な構成とし、TypeScript/esbuild/Vitestを使う当初案から、依存なしのJavaScript ES Modules / Node標準テストへ変更した。ビルドが必要になるStep 4で拡張へのパッケージ化を検討する。

## 実装

- `src/editor/model.js`: 空入力・行数・書記素数の検証。結合文字を分割しない。
- `src/emoji/layout.js`: 実際のglyph boundsを用い、上下左右8pxの余白に収める共通文字サイズを計算。
- `src/emoji/render.js`: フォント準備後のCanvas描画、透過／背景色、128×128のPNG生成と容量検証。
- `src/editor/view.js` とstyles.css: 入力・色・透過・拡大／明暗22pxプレビュー・名前付きFile生成。非同期描画には世代番号を付け古い結果を破棄する。
- 可読性による警告・登録制限は設けない。文字数と行数の入力制約は設計どおり。

## 確認結果

- Nodeのテスト2件が成功。空白・4行境界・12書記素境界・結合文字・配置余白を確認。
- Chromeの実Canvasで「ありがとう」「確／認／し／た（4行）」「ABCDEFGHIJKL」「か＋結合濁点」を透過と背景色ありで検証。8ケースすべて128×128 PNG、3,443〜5,818バイト。透過時の全辺alpha=0、背景ありの隅alpha=255を確認。
- UIの初期プレビュー表示と、arigatou.pngの生成（4,600バイト）を確認。ブラウザの既存Dark Readerが表示色を変更しているため、標準テーマの色の見た目とは区別する。
- ファイルをダウンロードせず、Fileを生成し `emoji-generated` イベントのdetailへ渡す。Slack送信は実装していない。

全OSのフォント差、全グリフ、キーボード操作の網羅、狭い画面での全操作は後続検証に残す。

## UI調整（ユーザー指定）

キャッチコピー、英語の装飾見出し、フッター、サンプル会話文を削除。入力欄は初期2行・最小高さ58px、主プレビューは80px（枠96px）、明暗プレビューは各22pxに縮小した。全体幅は最大560px。Chrome再読み込み後に表示を目視確認し、既存テスト2件も成功。
