# 縦伸縮の輪郭改善

ユーザーが選択した案1を実装する。文字画像の事後拡大をやめ、縦方向の変換を設定して文字を最終Canvasへ直接描画する。文字サイズと横位置の計算は既存処理を使う。実際の文字メトリクスと輪郭補正から縦範囲を求め、上下8pxの余白に収める。背景は変換前に描画する。

比較した案は、直接描画（採用）、高解像度で描いて縮小（負荷増）、画像の平滑化無効（段差が目立つ）。PNGは128×128px、128,000バイト未満。オフの描画結果・入力UI・下書き保持は維持する。

長い一行の水平線の輪郭でぼやけの回帰を検出し、全5書体・3揃え・複数行・空行・透明／背景ありについて余白と欠けを確認する。

実装時の判断: 文字輪郭のラスタライズにより、細い横線や句読点では文字メトリクス上の境界より最大1px内側へ収まることを許容する。8pxの余白へはみ出さず、追加の画像拡大は行わない。
